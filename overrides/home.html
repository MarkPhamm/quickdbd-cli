  1. The parser follows QuickDBD’s own parser step by step: same tables, same error messages. qdbd check --strict guarantees a file pastes back into QuickDBD.

See what a branch changes before you merge it

  • qdbd diff --base origin/main erd/ lists added, removed and changed tables, columns and relationships.
  • The GitHub Action posts it as one comment per pull request, updated on every push.
  • qdbd build --diff-base origin/main colours the changes in the diagram: new in green, changed in amber.

Before you install

Do I need a QuickDBD account?

No. qdbd only uses QuickDBD’s text syntax, and it isn’t affiliated with QuickDBD. Schemas copy back and forth between the two.

Does qdbd connect to my database?

No. It reads .txt or .dbml schema files or a dbt manifest.json; nothing connects to a warehouse.

Does my schema leave my machine?

Only if you turn sharing on (QDBD_ALLOW_SHARE=1) and run qdbd share, which uploads the page to a GitHub gist in your account (secret by default), publish it yourself (a tunnel, GitHub Pages), or connect an AI agent through qdbd mcp, whose answers go to your AI provider. Built pages load nothing from the network.

How big can a diagram get?

The demos go up to 200 tables. Search, selectors, regions and collapsed views keep large diagrams workable, and --select builds a page with just the part you need.

What do I need to install?

Python 3.11 or newer. No Node, Graphviz or browser: the layout engine runs inside Python.

Can I use it in CI?

Yes. The GitHub Action checks the schema, builds the page and comments on pull requests; any other CI can run the same commands. CI and Automation
