QuickDBD's syntax, unchanged

The parser follows QuickDBD's own, error messages included. A file that passes qdbd check --strict pastes back into QuickDBD as it is.

dbt docs generate
qdbd import dbt target/ -o erd/ \
  --infer-fks

Or generated from dbt

Primary keys come from unique and not_null tests, relationships from relationships tests. --infer-fks fills the gaps from column names.

Reviewed like code

The schema is text in git. qdbd diff and the GitHub Action put every change in the pull request, and the diagram colours what changed.

Follow any join, get the SQL

Click a table, type another one's name, and qdbd highlights the shortest chain of foreign keys between them, with a JOIN ready to paste.

FROM Invoice
JOIN Customer ON ...  -- table-level relationship
JOIN Campaign
  ON Campaign.CustomerRef0 = Customer.CustomerId
qdbd path schema/ --from Invoice --to Campaign

Questions

Do I need a QuickDBD account?

No. qdbd only uses QuickDBD's text syntax and isn't affiliated with QuickDBD. Schemas copy back and forth between the two.

Does qdbd connect to my database?

No. It reads .txt schema files or a dbt manifest.json. Nothing connects to a warehouse.

Does my schema leave my machine?

Only if you run qdbd share, which uploads the page to a GitHub gist in your account, secret by default. Built pages load nothing from the network.

What do I need to install?

Python 3.11 or newer. No Node, Graphviz or browser: the layout engine runs inside Python.

Can I run it in CI?

Yes. The GitHub Action checks the schema, builds the page and comments on pull requests, and any other CI can run the same commands. See CI and Automation.
