  1. The parser follows QuickDBD's own parser step by step: same tables, same error messages. qdbd check --strict guarantees a file pastes back into QuickDBD.
  2. The layout comes from ELK. Positions you drag are saved by table name, and new tables land next to the tables they relate to, so the diagram never reshuffles.
  3. One renderer draws the page in your browser and the PNG and SVG in the CLI, so an export always matches what you see.

# primary keys: unique + not_null tests
# relationships: relationships tests
# --infer-fks: customer_id → customers
qdbd check erd/                # QuickDBD's errors
qdbd serve erd/                # live editor
qdbd build erd/ -o erd.html    # one page
qdbd export erd/ -o erd.png    # or .svg .drawio
qdbd path erd/ --from Invoice --to Campaign

Frequently asked questions

Do I need a QuickDBD account?

No. qdbd only uses QuickDBD's text syntax, and it isn't affiliated with QuickDBD. Schemas copy back and forth between the two.

Does qdbd connect to my database?

No. It reads .txt schema files or a dbt manifest.json; nothing connects to a warehouse.

Does my schema leave my machine?

Only if you run qdbd share, which uploads the page to a GitHub gist in your account (secret by default), or connect an AI agent through qdbd mcp, whose answers go to your AI provider. Built pages load nothing from the network.

How big can a diagram get?

The demos go up to 200 tables. Search, selectors, regions and collapsed views keep large diagrams workable, and --select builds a page with just the part you need.

What do I need to install?

Python 3.11 or newer. No Node, Graphviz or browser: the layout engine runs inside Python.

Can I use it in CI?

Yes. The GitHub Action checks the schema, builds the page and comments on pull requests; any other CI can run the same commands. CI and Automation →
