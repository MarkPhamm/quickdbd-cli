# DBML Support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** qdbd reads DBML (dbdiagram.io) natively next to QuickDBD, converts between the two, and the VS Code extension, `serve` editor, docs and gallery all handle it.

**Architecture:** A new `dbml.py` (lexer → element parser → interpreter) turns a DBML file into the same `FileParse` that `parser.py` produces for QuickDBD, so the existing global resolve step (`_Resolver`) gives one `Schema` for mixed projects. `parser.parse_file` picks the syntax per file (`syntax_of`). `convert.py` writes QuickDBD or DBML text from a compiled schema and self-checks by recompiling.

**Tech Stack:** Python 3.11 stdlib (no new runtime deps), pytest, TypeScript (extension), CodeMirror 5 simple mode, TextMate grammar.

**Spec:** `docs/superpowers/specs/2026-10-22-dbml-design.md`

## Global Constraints

- Pip-only runtime; no Node/JS DBML parser bundle.
- Fidelity reference: `@dbml/parse` **10.3.1** (holistics/dbml commit `34108bb9346df5f22d5224549c106ff47ca931c8`).
- Every existing `.txt` under `examples/`, `gallery/`, `tests/` keeps building byte-identical (`syntax_of` must return `"quickdbd"` for all of them).
- Determinism: no timestamps/randomness in any output.
- The teammate's schema never enters the repo; tests use an invented look-alike.
- Versions: qdbd **0.2.0** (`pyproject.toml`, `src/quickdbd_cli/__init__.py`, README/docs action/pre-commit snippets); extension **0.4.0**, `MIN_VERSION = "0.2.0"`.
- Commit messages carry no AI attribution.

## Review Focus

1. A `.txt` QuickDBD file that merely mentions `Table`/`Ref` (e.g. a table named `Ref`, a comment `# Table x {`) must stay QuickDBD.
2. Windows line endings, tabs, BOM and a missing trailing newline in DBML must parse like LF/space files.
3. Quoted names with spaces/dots (`"order items"`, `"core"."users"`) must resolve in refs and display unencoded.
4. A DBML file with errors must still yield the tables that parsed (the extension's outline and `serve` keep working mid-edit), like `parser.py` does.
5. `qdbd serve` editing a `.dbml` file must save it back byte-for-byte and keep its layout positions.

Each has a test in the owning task (Task 2: 2, 3, 4; Task 3: 1; Task 5: 5).

**Interfaces:**
- Produces in `model.py`: `Table.group: str | None = None` (TableGroup name), `Table.color: str | None = None` (headercolor, lowercase `#rrggbb`/`#rgb`), `Table.end_line: int | None = None` (closing `}` line).
- Produces in `parser.py` `FileParse`: `syntax: str = "quickdbd"`, `unmodelled: list[tuple[int, str]]` (line, description of each accepted-but-not-drawn construct; `convert` turns them into warnings), `enums: dict[str, list[str]]` (enum name → values).
- Produces in `dbml.py`: `parse_dbml(text: str, path: str) -> FileParse` with `syntax="dbml"`, `settings={"casesensitive": True}`, tables keyed by `parser.encode(display_name)`, `aliases` (alias → table id), `rels` as `PendingRel(member1="<tableid>.<colid>", rel_type, member2, path, line, True)` using QuickDBD operators from `REL_TYPES`, diagnostics as `Diagnostic(path, line, msg, "error"|"warning")` (no "QuickDBD would reject this" prefix), `colors` for `// @color`.

Mapping decisions (spec tables are authoritative; these pin what the spec left open):
- Display name: `name` for schema `public` or none, else `schema.name`. Quoted parts are unquoted. `public.users` and `users` are one table.
- Operators: `>`→`>-`, `<`→`-<`, `-`→`-`, `<>`→`>-<`, `-?`/`?-`/`?-?`/`<?`/`?>` → zero-or variants (verify against the reference: each side's `?` makes that side zero-or).
- Composite `a.(x,y) op b.(p,q)`: one `PendingRel` per index pair, same line; count mismatch → error.
- Inline `ref: > t.c` on column `c0` of table `T`: `PendingRel("T.c0", op, "t.c")`.
- Column type: as written minus quotes; array types keep `[]`; `varchar(255)` intact.
- `note`/`Note` (table setting, `Note:` element, `Note { }` block) → `Table.comments` lines; column `note:` → `Column.comments`. `'''` strings: strip the common indentation and the first/last empty line (reference `note_normalize*` fixtures pin this).
- `// @tag:` lines directly above a `Table` → `Table.tags`; `// @color TAG #hex` anywhere → `FileParse.colors` (reuse `parser.TAG_RE`, `COLOR_RE`, `split_tags`). Other comments are dropped.
- `indexes`: `[pk]` (single or composite) → `pk` on each column; single-column `[unique]` → `unique`; everything else → `index` on each named column; expression parts ignored and recorded in `unmodelled`.
- `TablePartial` + `~name`: columns/settings/indexes injected in order; local definitions win, later partials beat earlier.
- `TableGroup g { a b }`: `Table.group = "g"` for each member (resolved by display name after all tables are known); a table in two groups → error like the reference.
- `Enum`, `checks`, `records`, `Project`, sticky `Note`, `Dep`, `Metadata`, `DiagramView`, `[inactive]`, ref `delete/update/color`, `TableGroup` colour/note: parsed and validated, each appended to `unmodelled` with its line.
- `use`/`reuse`: warning "qdbd ignores `use`; pass the imported file or its folder too"; an import with `as` → error.
- Errors: wording is qdbd's own; the line is the line of the offending token. After an error, recover at the next top-level element so later tables still parse.
